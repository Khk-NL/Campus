# 校园作品审核

## 发布边界

“我的仓库”显示本人全部项目，支持直接绑定 GitHub。每个项目由作者独立提交审核并显示状态；管理员核验华东师范大学归属、用途和内容，审核通过后进入校园作品、搜索与探索。讨论和回复按 Issue 模式直接交流，权限继承所属项目。

个人笔记、计划、课程及私有项目按账号隔离，继续同步。关注是用户与已公开项目的交互关系。

## 操作流程

1. 用户在“我的仓库”创建项目，填写介绍、华师大归属材料及可选的 GitHub 链接，保存为草稿。
2. 在该项目详情点击“提交审核”，单独进入审核队列。每个项目显示“待提交、待审核、已审核、待修改”及审核意见。
3. 管理员进入运营台“社区项目仓库”，默认显示待审核队列。打开“审核申请”查看项目介绍、GitHub、README 和归属材料，核验并勾选确认后点击“通过上架”；需补充材料时填写意见后“退回修改”。审核状态筛选可查看草稿、待审、通过及退回项目。
4. 审核通过的公开项目进入发现列表，其他用户可以关注、提 Issue 和回复。
5. 作者编辑项目后恢复草稿，重新提交后由管理员复审。项目所属讨论随项目可见范围变化。

## 实现与部署

- `1790210011_forge_project_review.js`：追加审核状态、学校归属材料、审核意见、归属核验及学校字段；公开读取要求 `approved + schoolVerified + ecnu`。
- 普通用户保存与提交只能写入 `draft` 或 `pending`，学校核验与审核意见由管理员维护。已有项目恢复草稿，由作者逐项提交审核。
- `ForgeRepository`：发现列表查询已审核项目；“我的仓库”读取自己的草稿及待审项目。
- 运营台 `AdminClient.reviewProject`：先读最新项目再写审核决定，批准前检查归属材料及学校范围。
- 增量部署命令：`sudo bash update-community.sh SOURCE_COMMIT 1790210011_forge_project_review.js`。脚本备份现有数据库后执行迁移。该审核迁移使用前向修正，回退旧权限须单独评估待审核内容的曝光影响。

## 验证

2026-10-10 本机真实 PocketBase：37 项通过，覆盖待审核隔离、自行审批拦截、管理员批准、逐项目状态隔离、GitHub 绑定、Issue/回复直接可用、编辑复审及私有项目隔离。运营台单元测试 17 项通过，Flutter 社区界面 5 项通过。公网与客户端的本轮结果记录在当天验收文档。
