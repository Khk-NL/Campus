## 2. 收件闭环

已完成：Brevo SMTP 设置核对、测试邮件 HTTP 204、未验证账号禁止登录、用户不能自行设置 Verified。204 表示邮件提交成功，收件和链接需要下面的实际步骤。

1. 在 App 用能查看收件箱的新邮箱注册，记录发送时间。
2. 查收验证信和垃圾邮件；如未收到，检查 Brevo 事务日志中的该次投递状态及失败原因。
3. 点击邮件里的验证链接，回 App 登录；验证前登录应被拒绝，验证后正常进入。
4. 从 App 请求密码重置，查收并打开重置信。账号持有人设置新密码后，回 App 确认新密码成功、旧密码失败。

需要账号持有人参与的原因：当前可访问接口只能证明邮件提交；邮箱收件箱尚未具备可操作会话，密码重置最后一步由持有人设置新密码。其余发送、错误反馈及服务端检查可继续自动完成。

## 3. 微信真机

1. 在安装微信的 Android 真机覆盖安装同一预览包。
2. 在微信开放平台核对 Android 包名 `cn.campus.campus_mobile` 与当前 APK 签名 MD5 `3b8a0599b4ce81f2f2932c8121c8b4e4`。
3. 选用真实、已核实的小程序入口，点击后应唤起目标小程序；返回 App 后原页面和登录状态保留。

本轮浏览器工具对微信应用详情页返回站点安全策略拒绝，平台侧核对需通过允许的人工操作完成。MuMu 当前环境也不能替代装有微信的真机。AppSecret 保持服务端配置，公开 AppID 与包签名按实际发布包核对。

## 4. 正式域名恢复

1. 等待阿里云初审，按通知接听审核电话、补正资料、完成后续短信核验，直到管局审核通过。
2. 在仓库根目录 PowerShell 执行下面的命令；HTTP 跳转、TLS 1.2、TLS 1.3、健康接口必须全部通过。

   ```powershell
   $env:CAMPULSE_CHECK_HOST = 'campus.scsldr.cn'
   node scripts/check-public-endpoint.mjs
   Remove-Item Env:CAMPULSE_CHECK_HOST
   ```

3. 同步切换移动端 PocketBase/AI URL 和 PocketBase `meta.appURL`，再检查验证及重置邮件链接。
4. 推送 main，由 GitHub Actions 构建，核对源码提交后覆盖安装，重测登录、笔记、PDF 与评分。

备案审核由接入商及管局处理，代码和服务器操作不能使审核提前通过。当前继续使用临时域名。具体配置步骤见 [域名备案流程](DOMAIN_FILING.md)。
