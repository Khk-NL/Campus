# Campulse 立项演示：技术问答速查

## 开场 30 秒

“Campulse 是一个面向学生的校园数字工作台。现在能演示四个入口：首页汇总、校园应用、课程空间和个人设置。课程是主对象，课表是课程的时间视图；进入一门课后，可以在本机保存学习任务、过程记录和来源证据。现阶段重点是把交互和数据边界做通，学校数据与 AI 服务没有冒充已接入。”

## 老师可能追问

| 问题 | 可以直接回答 |
| --- | --- |
| 用了什么技术？ | “客户端是 Flutter/Dart，后端是 NestJS/TypeScript，数据库层用 Prisma/PostgreSQL。移动端通过仓库接口取数据，学校差异放在大学适配器里。” |
| 没网还能演示吗？ | “可以。App 启动时探测 Campulse API；不可用时按数据来源回退到内置演示数据，并在界面标明来源。不是把演示数据说成真实教务数据。” |
| 课程记录存在哪里？ | “当前在手机本机用 SharedPreferences 保存，并用课程 ID 区分。它适合演示草稿，不具备多设备同步或正式用户权限隔离；后续要由 Campulse API 和数据库承接。” |
| 已经对接华东师大了吗？ | “视觉规范和高校适配层优先按华东师大设计。现有学校认证提供者只实现了授权地址构造；真实登录、课表和个人数据仍需校方授权与接口，今天的课程数据是演示数据。” |
| 智能体和 AI 能用吗？ | “智能体配置、资料关联和交互入口在前端可演示，也定义了远程调用接口；目前没有接入模型、文件解析或多人协作服务。按钮会明确提示未接入，不会生成假回答。” |
| 为什么把课表放在‘课程’里？ | “课表、搜索结果和课程列表都指向同一个课程 ID。学生先找到课程，再查看时间、任务、资料与学习记录，避免各功能各自成为孤立入口。” |
| 怎样验证不是静态图？ | “可以现场新建课程学习任务、填写问题和证据、保存后退出重进。Flutter 静态分析和自动化测试覆盖了导航、课表、记录保存与跨课程隔离。” |
| 下一步先做什么？ | “先把课程、学习记录和证据落到后端，补上登录身份与按课程/用户的权限校验，再考虑学校正式数据、教师反馈与 AI 能力。” |

## 三句边界

- 能现场操作并保存的，称“已完成本机前端闭环”。
- 只有界面和类型化接口的，称“已预留，远程未接入”。
- 需要校方凭据、权限或数据许可的，称“待授权”，不要说成已经同步。
