# Campulse 课程空间落地方案

> 状态：方案 + 本地前端演示已实现；远程服务未接入。2026-09-24 根据已登录的[参考平台学生端](https://dire.muedu.org/student)可见界面与 Campulse 现有代码整理。下表仅记录调研来源；Campulse 使用自己的课程空间结构与术语，不复制页面、标识或未公开实现，也不默认双方存在可用接口。

## 1. 观察与定位

已实际点开学生端的主要入口。学生端以“学习室 / 学习画像 / 我的课程”为主导航；选课界面说明“选课后仅展示该课程下的活动”。目前的活动目录有“知识库、学术协作 (Native)、agent builder、Wiki 知识库”。逐项观察如下：

| 入口 | 实际可见交互 | 尚未验证 |
| --- | --- | --- |
| 课程选择 | “我的课程”列出 1 门已加入课程（4 个活动）；点击“选择这门课”后活动目录仍显示这 4 项 | 选课按钮未出现明确成功提示，不能确认后台选择状态是否变化 |
| 知识库 | 工作区加载后显示新建知识库、文件注入说明、知识库集合；当前账号为 0 库 / 0 文件。新建表单只要求库名；页面列出 PDF、DOCX、MD、TXT、CSV 支持格式，并说明自动切片、向量化和索引 | 未创建库或上传文件，故格式兼容性、检索质量与权限仍待验证 |
| 学术协作 (Native) | 工作区加载后可见“新开探究”、历史记录、模型标识、分享探究、自动画布、代理选择、知识库/附件、严格引用和探究输入框；当前没有历史记录，分享按钮提示需先选择或创建会话 | 未创建会话或发送探究指令，故生成、协作、引用和分享效果仍待验证 |
| 探究文件管理 | 可切换知识库 RAG、附件全文上下文、CSV 数据集和 Wiki 条目；界面分别说明检索片段、全文输入、数据分析及 Wiki 背景注入用途 | 当前无库、文件或 Wiki 条目；未验证四类材料进入模型后的实际效果 |
| Agent Builder | 可填写名称、系统指令、能力说明；调节 Temp/Top-P/Top-K；选择绑定知识库和工具；有未保存前的对话预览、智能体列表和班级共享开关。实测未设系统指令时提示先设定；设定后发送一条普通概念问题，界面返回“未找到相关信息，所生成的内容全部基于LLM生成”的提示 | 该次未得到可核验的概念回答；未保存智能体，故未验证共享权限和持久化 |
| 工具选择器 | 列出代码执行、互联网检索、学术洞察三种能力及用途 | 未实际执行工具 |
| Wiki 知识库 | 可搜索、按课题和标签筛选；有统计、课题创建（名称/描述）与条目创建（名称/标签）表单；当前列表为空 | 未创建条目，故未验证后续编辑和内容编译 |
| 学习画像 | 按活动历史探究会话选择透视，页面说明可提取或更新多维评估；当前没有历史会话 | 评估维度、计算方式与反馈效果 |

公开登录页还介绍 Swarm 智能体协同、文献洞察和代码沙盒，属于产品宣介信息。学校[官方课程介绍](https://ed.ecnu.edu.cn/3f/42/c45914a737090/page.htm)证实“数智学研：生成式AI在学习与科研中的应用”是 2025 年获立项的通识课程，课程目标是人机协同素养，内容含提示词工程、Agent 构建、无代码数据分析和学术可视化；这说明平台更接近**课程实践环境**，不只是通用资料库。站点本身的公开独立说明未检索到，不能把课程介绍当成平台技术说明。

Campulse 的定位不应变成另一个完整教学平台，而是在现有“校园服务 + 个人事务 + 学生应用”工作台中，让**课程成为学习资料和过程记录的归属对象**：学生从课程进入，完成“提出问题 → 收集带出处的资料 → 记录过程 → 形成结论 → 回看反馈”。课表是同一课程的时间视图，课程详情、学习任务、资料夹与学习足迹共同使用课程 ID。参考平台的实测界面说明这类信息链有实际使用场景，但 Campulse 第一版优先做好自己的课程闭环。平台联动可在获得授权后评估，不以互通为立项成立条件。

## 2. 第一版边界：一个可验收的纵向闭环

| 能力 | 第一版交付 | 暂不包含 |
| --- | --- | --- |
| 课程与学习任务 | 从课程列表或课表详情进入同一课程空间；任务附目标和计划完成时间 | 自动读取教师平台课程、全校教学数据 |
| 学习记录 | 在课程内记录问题、过程笔记、资料出处、结论和待验证问题 | 伪造 AI 对话或多人实时协同 |
| 学习足迹 | 按课程回看本机学习记录，显示记录数、证据数和最近更新时间 | 无依据的能力分、自动评语 |
| 反馈 | 学生可修改结论并看到变更；预留教师反馈结构 | 未获授权时提交到教师平台 |

第一版演示使用明确标注的演示课程与资料。**当前前端阶段**只在本机保存，不把草稿冒充已同步记录；正式 MVP 才从 Campulse API 读取和保存，并处理断网状态。保留演示任务与学生自建任务的来源标签，避免身份混淆。

## 3. 技术接入点

现状依据：Campulse 已有 Flutter 四 Tab、课程展示模型、NestJS API、Prisma/PostgreSQL 和大学 Adapter；课程、公告、活动、任务主要仍是演示数据，ECNU 登录和开发者平台数据尚未真实接入，也没有课程活动管理后台。因此先实现 Campulse 自有数据闭环，不直接复用数智学研的账号或会话。

1. `packages/models`：定义 CourseTask、LearningRecord、Evidence、Reflection 的请求/响应契约与状态，不把任意 JSON 当通用模型。
2. `apps/api`：按“当前用户 → 课程 → 学习任务 → 学习记录”校验访问权限；新增任务列表、记录创建/读取/更新、证据与结论保存接口。Prisma schema、migration、模型同步变更。
3. `apps/mobile`：底部“课程”统一承载课程列表；课程表作为时间视图，课程列表、课表详情和全局搜索的课程详情均通向同一课程空间。课程空间内按学习任务、学习记录、资料夹、智能体和学习足迹组织功能。
4. 演示数据与真实数据隔离：种子活动使用显式 demo 标识。ECNU Adapter 以后只接入获批的身份和课程数据，不能把网页登录态当 API 凭据。

最小数据关系：`CourseTask(courseId, title, objective, source, deadline)` → `LearningRecord(taskId, ownerId, status)` → `Evidence(recordId, title, url, note)`、`Reflection(recordId, conclusion, openQuestions)`。每条记录保存创建/更新时间；引用资料保留标题和可访问 URL。真实课程 ID 与演示课程 ID 不混用。

## 4. 分期与前置条件

| 阶段 | 可交付结果 | 前置条件 / 验收 |
| --- | --- | --- |
| A. 需求核定（约 2–3 天） | 一页需求卡、3 个典型活动样例、字段和角色权限表 | 与老师确认是“参考功能”还是正式联动；确认演示数据可用范围 |
| B. Campulse 自有 MVP（约 2–3 周） | 课程 → 学习任务 → 学习记录 → 带出处的证据 → 结论 → 历史回看 | 新建、续写、刷新后可回看；用户不能读写他人记录；来源标签清楚 |
| C. 可解释反馈（约 1 周） | 完成度、证据覆盖、教师手写反馈的展示与修订记录 | 每项反馈可追溯到会话事实；不以“AI 评分”代替证据 |
| D. AI/Agent 试点（另行评估） | 从一类课程任务开始：配置 Prompt、限定资料范围、预览回答并附引用；教师审核后才可共享模板 | 获得资料使用权、模型/算力预算、隐私审查和质量测试数据；先不开放任意工具 |
| E. 平台联动/协作/代码沙盒（另行立项） | 经授权的 SSO/链接或 API；组内协作；受限的网页检索和隔离执行环境 | 对方提供正式接口与许可；完成权限、安全和资源配额设计 |

时间仅是 1–2 名开发者使用现有技术栈的粗估；ECNU 数据授权、教师平台联动和沙盒成本不计入 B/C 阶段。明天的立项报告宜承诺 B 阶段的闭环，C 作为增强项，D/E 作为条件明确的后续方向。

## 5. 验收场景与风险闸门

| 观察证据 | 测试情景 | 预期行为 |
| --- | --- | --- |
| 课程活动只对相关学生可见 | A 学生尝试打开 B 学生的会话地址 | API 拒绝访问，界面不泄露标题或资料 |
| 学习记录有可追溯资料 | 保存 2 条来源、1 条结论后退出重进 | 顺序、出处和内容保留；学习足迹统计与实际记录一致 |
| 演示与真实来源可分辨 | 后端缺失真实课程数据 | 显示演示数据标识，不声称已连接学校系统 |
| 后续 RAG 回答可核查 | 提问资料中没有答案的问题 | 明确“不足以回答”，不编造引用 |

风险闸门：没有正式授权，不读取数智学研内部接口、会话或用户数据；没有资料许可，不建设文献库；没有隔离与配额，不提供代码执行；没有身份与权限闭环，不开放跨用户协作。所有这些都不阻碍先交付 Campulse 自有 MVP。

## 6. 当前落地状态（2026-09-24）

- 底部导航改为“课程”，直接显示课程列表；“查看课程表”打开原有周次与单双周时间视图。课程列表、课表详情及搜索结果中的课程详情都能进入对应课程空间，而不是独立平行系统。
- 课程空间提供学习任务、学习记录、资料夹、智能体和学习足迹。进入一门课后可使用“我的课程笔记”开始记录，也可新建学习任务；内容按课程 ID 隔离。本地可填写问题和过程、添加网址证据、保存结论与待验证问题、退出后回看；还可建知识库名称和知识条目、配置智能体草稿。学习足迹只统计本地记录。
- 学习记录页有 RAG、附件全文、CSV、知识条目四种资料关联方式，以及严格引用、自动画布、AI 求助、群聊、分享等前端入口。文件上传、模型回答、多人协作、教师反馈尚**未接通**；界面明确告知，不生成假结果。
- 本机存储通过 `StudyRepository` 隔离，未来远程能力有类型化 `StudyRemoteGateway` 端口。建议资源路径和接入顺序见 [课程空间 API 接入约定](./COURSE_SPACE_API_CONTRACT.md)。当前演示内容只适合非敏感测试数据，清除应用数据会丢失本机草稿。
- 尚未完成原计划 B/C 阶段的服务端持久化、用户归属权限、真实课程同步和教师反馈。因此不能将当前演示描述为正式上线。
