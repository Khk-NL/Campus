## 后续验收顺序

1. 恢复服务器管理会话，读取实际 Caddy 配置及握手日志；保留其他站点配置，仅修改 Campulse 所需内容。Caddy 默认支持 TLS 1.2 和 1.3，不能只根据客户端错误盲改配置。
2. TLS 1.2 和 Dart HTTPS 均恢复后，运行 `scripts/registration_mail_probe.dart`。由邮箱实际收到邮件、最新链接验证和普通用户登录共同确认注册闭环。
3. 运行 `scripts/production_repository_test.dart`，确认笔记、课程、计划同步和用户隔离；它不能替代 APK 界面验收。
4. 安装 GitHub Actions 新构建 APK，实际点击验收登录后的课程、笔记保存与重新打开、计划完成与恢复、AI 回复及应用入口。身份验证界面需由用户亲自操作，之后继续自动点击验收。
5. 在安装微信的设备上测试真实小程序；没有微信时必须给出明确反馈，不能显示成功。

## 不应混淆的能力边界

ChatECNU 课程问答网关不等于完整 EduWork。资料索引、RAG 证据链、Quiz/Flashcards 等能力需按各自实现和实测结果验收，不能仅因网关在线就宣称全部可用。
