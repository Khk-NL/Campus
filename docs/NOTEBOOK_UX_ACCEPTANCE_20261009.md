## 发布与验收顺序

### 1. 更新网关

1. 固定 main 源码提交，在服务器独立 staging 获取网关文件并核对 Git blob 哈希。
2. 用 `/opt/campus/runtime/node-v22.23.3-linux-x64/bin/node` 执行锁定依赖安装和网关测试。
3. 备份 `/opt/campus/ai-gateway`，仅更新网关并重启 `campus-ai`。本轮沿用已有成果与全文集合，数据库迁移保持不变。
4. 执行 `scripts/notebook-studio-acceptance.mjs`，确认双账号隔离、全文、引用、生成、评分和连续对话。再检查新增编辑、分页接口。

### 2. 安装云构建 APK

1. 查看 GitHub Actions 的 Android Release 工作流，确认源码提交与本轮一致。
2. 查看 `release/Campulse-latest.json` 的 source commit、版本及 SHA-256，再下载 `campulse-preview` 中的 APK。
3. 覆盖安装，保留已有数据和签名；启动后确认原登录状态。
4. 在亮色与暗色、横屏与竖屏分别检查资料区域和页签。滚动到成果时，概览与输入框应离开可视区域。

### 3. 设备逐项验收

| 顺序 | 操作 | 通过条件 |
| --- | --- | --- |
| 1 | 登录普通账号，打开课程资料，选中含明确知识点的 Markdown/PDF | 所选资料与课程正确，云端同步成功 |
| 2 | 搜索一个原文中的完整词，再搜索一个原文不存在的词 | 前者显示对应片段与页/行，后者显示空结果；切页不带走搜索词 |
| 3 | 生成测验，逐题选答案并提交 | 显示成绩、解释和引用；未答完时有提示 |
| 4 | 修改测验题干并保存，再次作答 | 旧成绩清除，新内容重新读取一致 |
| 5 | 生成闪卡，展开答案，加入复习，选一个评分 | 显示保存成功和下次日期，到期队列更新 |
| 6 | 选择课程智能体，输入两个连续问题 | 显示真实回复、引用，并保留两轮消息 |
| 7 | 关闭 App 后重新启动，重新进入该课程 | 成果、成绩、复习时间及对话能读回 |
| 8 | 换第二个普通账号 | 第一个账号的笔记、成果与对话保持隔离 |

## 正式发布门槛

1. **备案**：按 [域名备案流程](DOMAIN_FILING.md) 完成阿里云备案。通过后重跑 `check-public-endpoint.mjs`，HTTP 跳转、TLS 1.2、TLS 1.3、健康接口四项都通过，再统一 App 配置、PocketBase appURL 和官网域名，重新云构建。
2. **微信真机**：在装有微信的 Android 手机上安装同一发布包，点击真实小程序入口；确认 AppID、包名、发布签名一致，能唤起小程序并返回 App。MuMu 的接口测试不能代替这一步。
3. **验证邮件**：用可实际收件的新邮箱从 App 注册；查收邮件、点击验证链接，再回 App 登录。记录投递时间及失败提示。
4. **密码重置**：从 App 请求重置并查收邮件。新密码由账号持有人在重置页面填写，随后用新密码登录，确认旧密码失效。
