# Campulse MVP：参考产品与实现边界

这份文档把讨论过的产品方向映射到当前代码。Campulse 仍以“校园服务入口 + 课程工作台”为主，不做 EduWork 的 Android 复制品，也不把学校官方服务伪装成自有服务。

这里的两个平台参考是 EduWork 与“数智学研”；`sp-study-courses` 是已有课程插件的实现参考，不是第三个必须接入的在线服务。讨论中的长篇改造提示包含未经验证的接口与远期设想，以下决策以当前公开资料和仓库实作为准。

| 参考 | 可借鉴的体验 | Campulse 的处理方式 | 目前状态 |
| --- | --- | --- | --- |
| [EduWork](https://github.com/ECNU/EduWork) | 围绕资料完成任务，制作学习材料 | 课程内预留 AI 调用边界；笔记正文由 Campulse 保存。EduWork 当前公开说明是本机桌面助手，不假设它已有可供手机直连的托管 AI API | `StudyRemoteGateway` 是接口，真实 AI 未接入 |
| [数智学研](https://dire.muedu.org/student) | 课程活动、资料、过程记录与反馈的整合思路 | 以课程为单位组织任务、证据、知识条目与学习足迹；不复制页面、名称、私有接口或用户数据 | 课程空间已有本机/PocketBase 记录；该站登录区未能通过公开网页核实完整功能 |
| [sp-study-courses](https://github.com/Khk-NL/sp-study-courses) | 多周课表、单双周与自定义周、课程导入、任务关联 | 课表保留在 Course 内；后续逐项核对逻辑再迁入，不能把插件存储直接当 Campulse 数据库 | Campulse 已有课表和课程入口；导入/去重能力需按现有实现核验 |

## 讨论中需要纠正的冲突

- “EduWork 有 Remote 方法”不等于“有公开、稳定、可从 Android 调用的在线服务”。其公开说明目前是本机桌面助手，不能据此承诺移动端直接接通；`StudyRemoteGateway` 暂时只定义 Campulse 自己的调用边界。真正接入时须核对授权、部署方式、API 文档和鉴权。
- “全部用 PocketBase”指本轮线上 MVP 的后端。PocketBase 自身使用嵌入式 SQLite；仓库里保留的本机演示存储不是另一套要同时维护的线上数据库。当前普通笔记必须在线登录才可跨设备读取，尚无离线合并和冲突解决。
- Hub 的首要工作是让学生快速找到并打开校园服务。项目发布与开发者生态可以逐步加入，但不应抢在真实可用的服务目录之前；课程表则始终从属于 Course。
- “参考数智学研”不等于已经核对其闭源页面全部功能。公开可核实的是课程理念，登录区不可访问时不得写成已实现的接口清单。
- 未来与学校或项目作者合作是可争取的方向，不是 MVP 功能依赖；当前不调用私有接口，不复用他人品牌名称。

## 数据归属

- PocketBase `campus_content`：试点校园服务目录及演示课程等公开内容。服务的 `launchTarget` 只负责跳转；没有授权接口时不抓取教务、图书馆等受保护数据。
- PocketBase `study_workspaces`：现有学习任务、过程记录、证据、知识条目和智能体草稿的个人快照。
- PocketBase `course_notes`：新建的独立课程笔记正文，按用户与课程隔离。外部 AI 将来只能通过明确接口读取授权范围内的副本，不能成为笔记唯一存储。
- 学校或外部平台：统一身份、模型、教学资源仍归各自平台。只有获得文档和授权后才接 API；否则只提供经核实的官方入口。

## 下一阶段验收顺序

1. 把课表与课程主页的课程 ID、周次规则和个人笔记关联稳定；核对 `sp-study-courses` 的导入、去重和冲突逻辑，再决定哪些值得移植。
2. 为笔记增加离线编辑、版本/冲突处理、附件和迁移旧课程记录的显式流程；当前“多端同步”仅指在线账号读取，不能保证同时编辑不覆盖。
3. 在实际服务文档和授权到位后，实现 `StudyRemoteGateway` 的 AI 适配器；先从只读问答与引用开始，AI 写回笔记必须由用户确认。
4. 扩充经人工核实的华东师大服务目录、搜索/收藏/最近使用闭环，并区分官网跳转、开放 API 和 Campulse 自有能力。
