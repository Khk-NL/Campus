## 项目与部署边界

- 本机仓库：`D:\Code\Projects\Campulse`；GitHub：`Khk-NL/Campus`。产品名为 Campulse，Android 包名仍为 `cn.campus.campus_mobile`，不要为了改名破坏安装更新和微信签名关联。
- Campus Hub 是校园服务快捷入口与学生项目发现；Course 是课表、课程资料、笔记、计划和学习记录工作台。项目首先适配华东师范大学，但不是学校官方应用，也不接管学校统一身份认证。
- Campulse 的账号、课程、笔记和工作台数据归 PocketBase；模型请求由自建 AI 网关调用 ChatECNU。生产复用 EduWork Knowledge Studio 的解析、分词、证据标签和导图布局，提供六项课程知识能力；当前 `/v1/status` 返回 `ready=true` 与 `integration=campulse-headless`。桌面 Host/Studio 的宿主进程、文件系统和媒体工具属于独立运行环境。
- `packages/*` 承载可复用领域模型；`adapters/ecnu` 的 OAuth2 授权 URL 构造已实现，但换码、刷新和获取学生资料仍会抛出未实现错误。`apps/api` 是早期 NestJS/Prisma 实现，**不在当前服务器运行链路中**；它的写接口尚无认证和限流，不能直接部署到公网。生产 App 使用 PocketBase 分支；不要把旧 REST/PostgreSQL 文档当成现网说明。
- 阿里云轻量服务器同时运行其他网站。Caddy 管理 80/443：`campus.scsldr.cn` 和 `campus.allezafrique.cn` 的 `/ai/*` 转发到本机 AI 网关 `127.0.0.1:8787`，其余转发到 PocketBase `127.0.0.1:8090`。两个后端均由 systemd 启动，不能另起公网代理占用端口。网关现已包含卡片复习路由，使用 `/opt/campus/runtime/node-v22.23.3-linux-x64/bin/node` 与 `ts-fsrs 5.4.2`；生产数据库已含 PDF 字段和卡片集合。
- 生产 APK 只通过 `.github/workflows/android-release.yml` 在 GitHub Actions 构建，发布到 `campulse-preview` Release 并更新仓库 `release/`。不要用本机脚本覆盖发布资产或随意更换 APK 签名。

## 临时可用性配置：必须记得撤销

外部访问 `campus.scsldr.cn` 时，TLS 握手会被重置，而同一服务器上的旧域名可用。为先恢复多用户 App：

1. `apps/mobile/config/eduwork.production.example.json` 的 PocketBase 和 AI 网关 URL 暂指向 `https://campus.allezafrique.cn`。
2. 生产 PocketBase `meta.appURL` 也暂改为旧域名，使验证/重置邮件链接避开故障域名；已用只读设置接口核对，发件人仍保持原值。
3. 官网的目标域名仍是 `campus.scsldr.cn`。不要把这种双域名状态误称为最终部署。

2026-10-09 已在腾讯云和阿里云确认 `scsldr.cn` 未备案，公网 HTTP 的阿里云备案拦截页提供了直接证据。按 [正式域名恢复与备案流程](DOMAIN_FILING.md)完成“有主体新增服务”备案。正式域名的 HTTP 跳转、外部 TLS 1.2、TLS 1.3、健康页和 MuMu 登录都通过后，将上述两处 URL 改回正式域名并重新云构建验收。PocketBase App URL 可用 `scripts/remote-acceptance.mjs --set-app-url` 修改；目标由 `CAMPULSE_APP_URL` 指定，脚本只允许两个已知 HTTPS 域名。

## 推荐后续顺序

1. **域名和注册闭环**：按已校验的阿里云“有主体新增服务”流程备案 `scsldr.cn`，审核后重测外部 TLS；用真实收件箱完成注册验证、登录、密码重置，查看 Brevo 事务日志。
2. **故障预防**：在阿里云云监控配置磁盘 I/O、空间和实例不可用告警，测试通知；保留 `atop`，下次故障用 `/var/log/atop/` 回看进程。不要未经定位就清理共享服务器数据或重置防火墙。
3. **内容运营**：在 PocketBase 管理后台发布实际 ECNU 服务与学生应用；确认可访问的目标 URL、来源与授权，保留 `demo` 标记给示例内容。App 将云端示例标为演示数据是预期行为，不代表断网。
4. **真机微信验收**：安装微信的 Android 真机下载最新 GitHub Release APK，核对开放平台的包名与 APK 签名摘要，再测试小程序唤起。不要将 AppSecret 编译进 APK。
5. **EduWork 独立开发阶段**：先确定上游许可、Host 部署和多租户边界，再实现受限 worker、每用户工作区、任务队列、产物持久化与清理。ChatECNU 问答已可用，但不能替代这些工程。
